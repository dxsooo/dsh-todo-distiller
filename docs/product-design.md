# 产品设计

## 背景

目标是一个面向工作场景的"助理 Agent",最终以 DSH 的 Agent Preset / Bundle 形式交付:家人安装后在 DSH 里启用"助理"预设即可使用,不需要自己配置一堆插件。

助理要做的事:

- 从 IM(微信、钉钉)、电话、微信电话、腾讯会议、Word/PPT 文档中获取原始信息。
- 提炼出待办、日程、事项之间的业务关系,以及完成后的纪要。
- 到点提醒、会前提醒、待办逾期提醒。

## 当前阶段(MVP)

只做一件事:**把文本里的待办和日程整理成结构化结果,并给出提醒建议。**

形态是一个独立的 DSH 插件,注册一个工具 `dsh_todo_distiller`。使用方式是在 DSH 对话里把文本交给模型,模型调用该工具。

### 本阶段不做

- 微信、钉钉真实 API。
- 电话、微信电话、腾讯会议录音,语音转写(ASR)。
- 真实的提醒推送。
- UI 面板。
- Agent Preset 打包。
- 发布 npm、建 GitHub 仓库。
- 修改 DSH 宿主源码。

## 设计原则

1. **自然语言交给模型,确定性行为交给软件。** 模型负责理解文本、把"周五前"这类表达换算成时间;软件负责校验、计算提醒、保存关联,不让模型临场编辑这些结果。理由:模型越来越强但不会降到零错误,而 token 是硬成本。
2. **不改宿主。** 一切通过 DSH 公开的插件机制完成。
3. **最少依赖。** 优先用 Node 内置模块和 DSH 已提供的能力。
4. **不确定就说出来。** 模型的假设写进 `timeAssumption`,没有确定时间的事项进入 `unresolved`。

## 路线图

| 阶段 | 内容 | 状态 |
|---|---|---|
| 1 | 文本 → 待办/日程/提醒建议(本插件) | 已实现,对话验证通过 |
| 2 | 端到端:侧栏专属页面,拖入 markdown 会议记录 → 提炼 → 写入 macOS 提醒事项;每日会话;跨天关联 | 0.1.0-rc.2,家人试用中 |
| 3 | 更多入口:Word/PDF/Excel、截图、录音(ASR)、AI 耳机、IM 监听。每类入口产出文本和来源引用,可做成可选的独立 bundle | 未开始 |
| 4 | 通话与会议录音:ASR 后接入同一工具 | 未开始 |
| 5 | 更多出口:日历事件、其他平台的提醒 | 未开始 |
